# Док Топ (DOC.TOP) — сервис записи к врачам в Москве

Демонстрационный сайт медицинского агрегатора: каталог врачей и клиник, цены на
услуги, онлайн-запись на приём. Собран по образцу популярных сервисов
(mosgormed.ru, docdoc.ru) с сохранением контактов и юридической информации
бренда «Док Топ».

> **Живая демо-версия:** после включения GitHub Pages сайт доступен по адресу
> `https://<ваш-логин>.github.io/doc-top/` (Settings → Pages → Source: GitHub Actions).

## Стек

- **Next.js 16** (App Router) + **React 19** + TypeScript
- **Tailwind CSS 4** + shadcn/ui (Radix primitives)
- **Prisma + SQLite** — хранение заявок (запись, подбор врача, обратная связь)
- Шрифты: Manrope (латиница + кириллица)

## Возможности

- Главная: поиск по врачам, популярные специальности, преимущества, топ-врачи,
  цены, клиники, FAQ, форма «помочь с подбором»
- Каталог врачей с фильтрами: специальность, метро, «сегодня на смене», выезд
  на дом; сортировка по рейтингу/стажу/цене
- Карточка врача: цены на услуги, отзывы, стаж, кнопка записи
- Клиники, услуги и цены (6 категорий), о сервисе, контакты, FAQ
- Политика обработки персональных данных и правила публикации отзывов
- Формы записи с маской телефона `+7 (999) 123-45-67` и валидацией,
  заявки сохраняются в SQLite через `POST /api/requests`

## Быстрый старт

```bash
bun install
bun run db:push      # создать SQLite-базу (prisma/schema.prisma)
bun run dev          # http://localhost:3000
```

## Скрипты

| Скрипт              | Назначение                                                        |
| ------------------- | ----------------------------------------------------------------- |
| `bun run dev`       | Dev-сервер на порту 3000                                          |
| `bun run build`     | Продакшен-сборка (standalone, с API-роутами)                      |
| `bun run start`     | Запуск продакшен-сборки                                           |
| `bun run build:static` | Статическая сборка для GitHub Pages (демо-режим форм)          |
| `bun run db:push`   | Синхронизация Prisma-схемы с базой                                 |

## Публикация

### GitHub Pages (демо для заказчика)

1. Запушьте репозиторий в ветку `main`.
2. В настройках репозитория: **Settings → Pages → Build and deployment →
   Source: GitHub Actions**.
3. Workflow `.github/workflows/deploy-pages.yml` соберёт статическую версию и
   опубликует её на `https://<логин>.github.io/<имя-репо>/`.

В статической сборке (`build:static`) серверных API нет, поэтому формы
работают в демонстрационном режиме: заявка «принимается», но никуда не
сохраняется. Это удобно для показа заказчику.

### Vercel / любой Node-хостинг (полная версия с сохранением заявок)

1. Импортируйте репозиторий в Vercel — ничего настраивать не нужно
   (сборка `bun run build`, output: standalone).
2. Задайте переменную окружения `DATABASE_URL` (SQLite-файл) и выполните
   `bun run db:push`.

Заявки можно посмотреть в базе: `sqlite3 db/custom.db "SELECT * FROM BookingRequest"`.

## Структура проекта

```
src/
├── app/
│   ├── api/requests/route.ts   # POST: сохранение заявок в SQLite
│   ├── layout.tsx              # метаданные, шрифт, тосты
│   └── page.tsx                # hash-роутер (#/doctors, #/doctor/..., #/contacts)
├── components/
│   ├── site/                   # страницы и виджеты сайта
│   │   ├── home-page.tsx, doctors-page.tsx, clinics-page.tsx, ...
│   │   ├── booking-dialog.tsx  # модальное окно записи
│   │   ├── header.tsx / footer.tsx
│   │   └── ...
│   └── ui/                     # shadcn/ui компоненты
└── lib/
    ├── data.ts                 # демо-данные: врачи, клиники, услуги, FAQ
    ├── site.ts                 # бренд, контакты, юридическая информация
    ├── submit-request.ts       # отправка форм (+ демо-режим для Pages)
    ├── store.ts                # zustand-стор (состояние записи)
    └── db.ts                   # Prisma client
```
